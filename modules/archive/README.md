## Peridot Archive 仕組み

Peridot Archive は Peridot 独自のアーカイブ形式で、複数のアセットファイルを一つのファイルにまとめたものになります。
（いわゆる Asset Bundle みたいなものを実現する機能）

## 共通

- 整数データは以下のどちらかで格納される
  - `VariableUInt` `VariableULong`により可変長で格納される
  - 固定長の場合は Little Endian で格納される
- 文字列データは PascalStr の形式で格納される
  - 先頭に`VariableUInt`でバイト長を格納し、その後ろに UTF-8 でのバイト列が並ぶ

## 大まかなファイル構造

- ファイルヘッダ
- コンテンツ部（ここ以降のデータは圧縮されている場合がある）
  - コンテンツヘッダ
  - ハッシュツリーブロック
  - 実名リストブロック
  - データブロック

### ファイルヘッダ

圧縮形式によって異なる

#### 共通部分

- 先頭 4 バイトはファイルシグネチャであり、固定のバイト列が入る
- `Checksum`: CRC-32 (IEEE 802.3) アルゴリズムで計算されるコンテンツ部（圧縮状態）のチェックサム

#### 圧縮なし

```
+-----------------+----------------+
| 'p' 'a' 'r' ' ' | checksum (u32) |
+-----------------+----------------+
```

#### 圧縮あり

```
+-----------------+-------------------+----------------+
| 'p' 'a' 'r'  _  | Byte Length (u32) | Checksum (u32) |
+-----------------+-------------------+----------------+
```

- シグネチャの 4 バイト目は圧縮方式を表す
  - `d`: zlib
  - `z`: lz4
  - `1`: zstd(11)
- `Byte Length`: 圧縮前のコンテンツ部のバイト長で、展開時のヒントとして使用される

### コンテンツヘッダ

```
+-------------------+----------------------+-----------------------------+
| Content Flag (u8) | Hash Tree Size (u32) | Exact Name Block Size (u64) |
+-------------------+----------------------+-----------------------------+
```

- `Content Flag`: コンテンツ部の各種フラグを格納する
  - `0x01`: ルートのハッシュツリーは Exact Tree であることを示す
- `Hash Tree Size`: ハッシュツリーブロックのサイズ の 1/8 の値
  - つまり下位 3 ビットは格納されていない（読み出し時にシフトして 0 で埋める）
- `Exact Name Block Size`: 実名リストブロックのサイズ（バイト長）

### ハッシュツリーブロック

アセット名を XXH3 でハッシュしたものをキーとして、B-Tree のような構造で持つ。

子要素の形によって 2 種類に分かれる。

#### Exact Tree

子要素が実名リストブロック内へのポインタのみの場合は Exact Tree となる。構造としては、キーを昇順でソートした形で以下の構造のデータ（エントリ）が並んでいる。

```
+------------------+-------------------------------+
| Hashed Key (u64) | Exact Name List Pointer (u64) |
+------------------+-------------------------------+
```

- `Hashed Key`: キー（アセット名のハッシュ）
- `Exact Name List Pointer`: 実名リストブロック内の、同一ハッシュとなったアセット名のリストの先頭へのポインタ

ルート以外の Exact Tree はツリーデータの前にエントリの数（`u16`）が格納されている。

#### Normal Tree

子要素がツリーである場合は Normal Tree となる。構造としては、キーを昇順でソートした形で以下の構造のデータ（エントリ）が並んでいる。

```
+------------------+-------------------------------+-----------------------+
| Hashed Key (u64) | Exact Name List Pointer (u64) | SubTree Pointer (u64) |
+------------------+-------------------------------+-----------------------+
```

- `Hashed Key`と`Exact Name List Pointer`については Exact Tree のものと同一
- `SubTree Pointer`: このキーより小さく、一つ前のエントリのキーより大きいキーを集めたサブツリーへのポインタ
  - 最初のエントリの場合は、このキーより小さいキーを集めたサブツリーとなる
  - MSB の 1 ビット（`0x8000_0000_0000_0000`）はサブツリーが Exact Tree かどうかを表す

Normal Tree は最後のエントリの後に追加で 8 バイトのポインタ値を格納している。
これはこのツリーに含まれるどのキーよりも大きいキーを集めたサブツリーへのポインタとなっている。

### 実名リストブロック

万が一にもハッシュが衝突した場合、この実名リストを辿って正しいアセットを識別することになる。

このブロックは以下のような構造のデータが並んだ形となっている。

```
+----------------------------+---------------------------------------------------------------------------------+
|                            | +------------------+-----------------------------+------------------------+     |
| Entry Count (VariableUInt) | | Asset Name (str) | Byte Length (VariableULong) | Offset (VariableULong) | ... |
|                            | +------------------+-----------------------------+------------------------+     |
+----------------------------+---------------------------------------------------------------------------------+
```

- `Entry Count`: この実名リストの要素数
- `Asset Name`: 実際のアセット名
- `Byte Length`: アセットのバイト長
- `Offset`: アセットデータがデータブロック内のどこに格納されているかを表す

このリストはアセット名でソートされている必要はない。

### データブロック

アセットの実際のデータがそのまま格納されている

## アセットロードの流れ

(非圧縮+チェックサム検証なしの場合。どちらかを満たさない（圧縮形式 or チェックサム検証あり）の場合はファイルの内容がすべてオンメモリに展開されるため、大きなアーカイブファイルを作る場合は要注意)

1. アーカイブファイルを開く
1. コンテンツ部からハッシュツリーブロックと実名リストブロックの範囲を割り出し、メモリにマッピングする
   - アセットエントリは頻繁に参照されるのと、データブロックと比べてそこまで大きくならないだろうから、Peridot ではこの部分だけメモリにマップしている
1. 指定されたアセット名のハッシュを得る
1. ハッシュをもとにハッシュツリー内を検索し、実名リストブロックへのポインタを得る
   - 最初に探すべきハッシュツリー（Root Tree）は、ハッシュツリーブロックの先頭部分の特定サイズの領域にある
     - 現状はこの先頭部分のサイズはおおよそ 8192 バイト（ファイルヘッダ/コンテンツヘッダを含む）となっている
     - ただし Root Tree が Exact Tree の場合は 8192 バイト以下になることがある。Exact Tree の場合はコンテンツヘッダの Hash Tree Size と一致する
1. 実名リストブロックを探索し、アセットのサイズとオフセットの情報を得る
   - 実名リストはソートされていないため、線形探索を行う
1. データブロック内の所定の範囲をアセットデータとして読み込む
